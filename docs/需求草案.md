# 需求草案

版本：1.0  
状态：首版需求已确认

## 产品定位

面向个人使用的 macOS 菜单栏状态监控应用，以极简 UI 和尽可能低的后台功耗为最高优先级。

- 应用显示名：`edison`（全小写）

## 目标运行环境

- 设备：MacBook Air
- 芯片：Apple M5
- 内存与存储：16 GB + 512 GB
- 当前系统：macOS 26.5.2

## 已确认功能

1. 菜单栏常驻固定图标，不在菜单栏直接显示实时数值。
2. 菜单栏图标采用带数字 `10` 的球衣造型。
3. 点击图标后显示参考 State 的卡片式状态面板。
4. 显示当前 CPU 使用情况，信息组织和图表风格参考 State。
5. 显示当前 GPU 使用情况，信息组织和图表风格参考 State。
6. 显示 Mac 温度。
7. 不需要显示内存或风扇数据。
8. 显示 AirPods Pro 左耳、右耳和充电盒电量。
9. 显示 AirPods Pro 的连接与充电状态，但不发送低电量通知。
10. 显示 Codex 的 5 小时额度、每周额度以及距离额度重置的时间。
11. Codex 卡片根据账号实际返回的额度窗口动态显示；当前账号截图只出现每周额度时，不显示无数据的 5 小时占位项。
12. 显示 Mac 本次启动后已运行的时长，不显示具体开机时刻。
13. CPU 与 GPU 图表只在面板打开时刷新，目标频率为每秒一次，展示最近一分钟。
14. 面板关闭后停止维护 CPU/GPU 历史图表。
15. 支持登录后自动启动应用。
16. 应用只存在于菜单栏，不显示在 Dock 中。
17. 首版不提供 AirPods、温度或 Codex 用量提醒。
18. 接受自行安装的非沙盒应用形态，不以 Mac App Store 上架为目标。

## UI 要求

- 整体简洁、美观、紧凑。
- 参考 State 的两列卡片布局和信息组织方式。
- 适配 macOS 26 的玻璃视觉效果。
- 数据层级清晰，不为装饰牺牲可读性。
- 面板尺寸和信息密度适合快速扫一眼，而不是完整仪表盘。
- 菜单栏球衣图标应在浅色与深色菜单栏中都清晰可辨。
- 菜单栏与应用图标均保持简洁的单色 `10` 号球衣造型。
- 温度卡片以大字显示“芯片最高温度”，并以小字显示系统热状态；数值不可用时只显示热状态。

## 已确认面板结构

- 顶部：应用标题或简洁状态区，并显示 Mac 已运行时长。
- 第一排：CPU、GPU 两张卡片。
- 第二排：温度、AirPods 两张卡片。
- 第三排：Codex 横跨两列的大卡片。
- 底部：低干扰的设置入口。

## 已确认设置项

- 登录后自动启动开关。
- Codex 手动刷新。
- 关于 `edison`。
- 退出应用。

## Codex 用量数据方案

- 不通过辅助功能模拟点击左下角菜单，也不通过 OCR 或高频截图读取。
- 优先采用 Codex 官方 App Server 的 `account/rateLimits/read` 接口读取额度窗口。
- 支持 App Server 返回的多额度桶；用 `windowDurationMins` 区分窗口，并依据 `usedPercent` 计算剩余比例。
- 使用 `resetsAt` 展示下次重置日期或倒计时。
- 优先在面板打开时按需刷新，并缓存最后一次成功结果；避免为了一个低频指标常驻高频轮询。
- 账号没有返回某个额度窗口时，该项不显示；数据暂时不可用时展示“暂不可用”和最后更新时间。

## 性能与功耗要求

- 低功耗是核心验收标准。
- 面板打开时可提高刷新频率，关闭后自动降频或暂停。
- AirPods 和 Codex 用量优先使用事件触发、缓存或低频刷新。
- 避免持续调用高开销命令或启动常驻子进程。
- 避免无意义动画、定时器和高频系统唤醒。
- 开发阶段需要记录空闲 CPU、内存、能耗影响和系统唤醒情况。

## 待验证事项

- CPU、GPU 与温度数据在目标 macOS 和硬件上的最佳低功耗采集方式。
- AirPods 电量在连接、放回充电盒和断开时可获得的数据范围与更新时机。
- Codex App Server 在目标 Mac 上如何复用当前 Codex 登录状态，以及最合适的按需生命周期。
- 仅支持 macOS 26，还是同时兼容较早版本。
- `10` 号球衣图标的最终轮廓细节由首版视觉稿与菜单栏实机效果迭代确定。

## 已确认技术方向

- 原生 SwiftUI `MenuBarExtra` 窗口式面板，使用 `LSUIElement` 隐藏 Dock 图标。
- CPU 使用公开 Mach API；GPU 使用 M5 AGX 的 IOKit 性能统计并允许失败降级。
- 温度优先显示“芯片最高温度”，私有数值读取失败时退化为系统热状态。
- AirPods 使用 IOBluetooth 监听连接，通过系统 `pmset` 的 XML 输出按需读取三部件状态。
- Codex 使用官方 App Server 额度接口，按需启动、查询后退出。
- 登录启动使用系统 `SMAppService.mainApp`。
- 首版技术定位为自用非沙盒应用，用户已确认接受。

## 初步刷新策略

- 状态面板打开：CPU、GPU 与温度以每秒一次为目标频率刷新；CPU/GPU 图表保留最近一分钟。
- 状态面板关闭：停止 CPU/GPU 图表采样；温度无后台需求时也暂停。
- AirPods 状态：连接状态变化时更新，必要时辅以低频校验。
- Codex 用量：打开面板时按需读取，平时使用缓存，并提供手动刷新入口。

## 验收方向

- 菜单栏常驻稳定，点击响应及时。
- CPU、GPU、温度、AirPods、Codex 与开机时间的数据来源明确，异常或不可用时有清晰状态提示。
- UI 在目标 macOS 上协调、清晰且符合原生交互。
- 长时间后台运行不会造成明显耗电、发热或持续高频唤醒。
- 退出应用后不残留后台进程。
- 登录后自动启动可靠，并允许用户随时关闭。
